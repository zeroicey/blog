The website you're reading right now is the tutorial itself — it's generated by Hugo, hosted on Cloudflare Pages, images served from Cloudflare R2, with built-in site search and a GitHub-powered comment section. The whole setup costs **nothing in server fees**, only the domain (a few dozen yuan per year).

This post documents the complete journey from zero to launch, so you can build an identical blog by following along.

# Tech Stack Overview

Here's the full pipeline:

| Component | Choice | Why |
|---|---|---|
| Static site generator | Hugo (extended) | Single binary, second-fast builds, native multilingual |
| Theme | hugo-coder | Clean, built-in multilingual/dark mode/comment extension points |
| Code hosting | GitHub | Free, seamless Cloudflare Pages integration |
| Deployment | Cloudflare Pages | Free, auto-build, global CDN |
| Image hosting | Cloudflare R2 + custom domain | 10GB free tier, zero egress fees |
| Site search | Pagefind | Pure static index, no backend, free |
| Comments | giscus | Based on GitHub Discussions, zero database |
| Domain | zeroicey.me (managed in Cloudflare) | DNS and CDN in one place, simplest setup |

# Step 1: Install Hugo

Hugo comes in two flavors — the **extended version is required** (needed for SCSS support, which most mainstream themes require).

macOS:

```bash
brew install hugo
```

For Linux / Windows or other systems, see the [official installation docs](https://gohugo.io/installation/), or grab a release binary directly.

Verify:

```bash
hugo version
# hugo v0.161.1+extended ... VendorInfo=Homebrew
```

Make sure the version says **extended**.

# Step 2: Create the Site and Install a Theme

```bash
hugo new site blog
cd blog
git init
```

Then install a theme. I use [hugo-coder](https://github.com/luizdepra/hugo-coder), added as a **git submodule** (so you can `git pull` to update it later):

```bash
git submodule add https://github.com/luizdepra/hugo-coder.git themes/hugo-coder
```

Point the theme in `hugo.toml`:

```toml
theme = 'hugo-coder'
```

# Step 3: Configure the Site

Here's the core of my `hugo.toml` (the full version is in the blog repo):

```toml
baseURL = 'https://zeroicey.me/'
theme = 'hugo-coder'
defaultContentLanguage = 'zh-cn'

[pagination]
  pagerSize = 10

[markup]
  [markup.goldmark.renderer]
    unsafe = true   # allow raw HTML in content

[params]
  avatarURL = 'images/avatar.webp'
  since = 2026
  colorScheme = 'auto'   # follow system light/dark
  preconnect = ['https://s3.blog.zeroicey.me']  # preconnect to image CDN
```

## Multilingual config

This blog is bilingual (Chinese + English), which Hugo supports natively:

```toml
defaultContentLanguage = 'zh-cn'

[languages.zh-cn]
  label = '中文'
  locale = 'zh-CN'
  title = '雪宁韵'
  weight = 1

[languages.en]
  label = 'English'
  locale = 'en-US'
  title = 'zeroicey'
  weight = 2
```

## Navigation menu

```toml
[[languages.zh-cn.menu.main]]
  name = '博客'
  weight = 1
  url = 'posts/'

[[languages.zh-cn.menu.main]]
  name = '关于'
  weight = 2
  url = 'about/'
```

# Step 4: Write Your First Post

Hugo posts are Markdown files with front matter:

```markdown
+++
title = 'Post title'
date = '2026-08-08T14:30:00+08:00'
draft = false
tags = ['tag1', 'tag2']
+++

Body...
```

For a bilingual site, write a pair of files: `content/posts/xxx.md` for Chinese and `xxx.en.md` for the English translation, with the same `date` in both.

Preview locally (including drafts):

```bash
hugo server -D
# open http://localhost:1313
```

Build check:

```bash
hugo --gc --minify
```

# Step 5: Image Hosting (Cloudflare R2)

Blog images live in an R2 bucket, served publicly via a custom domain (`s3.blog.zeroicey.me`). R2 offers 10GB free storage with **zero egress fees** — essentially free for a blog.

Create the bucket:

```bash
npx wrangler r2 bucket create blog
```

In the Cloudflare dashboard, bind a custom domain to the bucket (R2 → Settings → Custom Domains → enter `s3.blog.zeroicey.me`; the CNAME is created automatically).

Upload an image:

```bash
npx wrangler r2 object put blog/20260808123835.webp --file=~/Pictures/screenshot.webp --remote
```

> **Important**: you MUST add `--remote`! Without it, the object is only written to a local emulator and returns 404 online.

Verify immediately after uploading:

```bash
curl -s -o /dev/null -w "%{http_code}" https://s3.blog.zeroicey.me/20260808123835.webp
# 200 means it works
```

Reference the public URL directly in posts:

```markdown
![screenshot](https://s3.blog.zeroicey.me/20260808123835.webp)
```

# Step 6: Site Search (Pagefind)

Hugo has no built-in search; the community-standard solution is **Pagefind** — it generates a search index at build time and searches entirely client-side, no backend needed.

Generate the index after building:

```bash
npx --yes pagefind --site public
```

Then add a search button + modal UI to the site. I implemented it in `layouts/_partials/search.html`:

- A magnifier button in the nav bar that opens a search modal
- Lazily loads `/pagefind/pagefind-ui.js` (doesn't slow down first paint)
- Supports both Chinese and English UI (via Hugo's i18n translations)

Note that the Cloudflare Pages build command must **include the pagefind step** (see Step 8).

# Step 7: GitHub Comments (giscus)

I chose **giscus** for comments: comments are stored in your repository's GitHub Discussions, and visitors comment with their GitHub account — zero database, zero cost.

The `hugo-coder` theme has built-in giscus support. You need to:

1. Enable Discussions on the repo (Settings → Features → Discussions)
2. Install the [giscus App](https://github.com/apps/giscus) and authorize it for the repo
3. Configure `hugo.toml`:

```toml
[params.giscus]
  repo = 'zeroicey/blog'
  repoID = 'R_kgDOSjjc-g'
  category = 'General'
  categoryID = 'DIC_kwDOSjjc-s4DC64_'
  mapping = 'pathname'
  theme = 'preferred_color_scheme'
```

`repoID` and `categoryID` are GitHub internal IDs — generate them on [giscus.app](https://giscus.app), or query them via the GitHub API:

```bash
gh api graphql -f query='query {
  repository(owner: "zeroicey", name: "blog") {
    id
    discussionCategories(first: 20) { nodes { id name } }
  }
}'
```

I also made a small improvement by overriding the theme partial so the comment UI language **follows the article language** (Chinese posts show the Chinese comment UI, English posts show English).

# Step 8: Deploy to Cloudflare Pages

Cloudflare Pages has **Git integration**: once connected to your GitHub repo, every push to `main` triggers an automatic build and deploy.

In the Cloudflare dashboard: Workers & Pages → Create → Pages → Connect to Git → select the repo.

## Key: build configuration

**Build command** (this matters — the Hugo preinstalled in Cloudflare's cloud is too old and doesn't support the modern config format, so you must download a fresh one):

```bash
curl -sL https://github.com/gohugoio/hugo/releases/download/v0.161.1/hugo_extended_0.161.1_linux-amd64.tar.gz | tar -xz && ./hugo --gc --minify && npx --yes pagefind --site public
```

**Output directory**:

```
public
```

After that, deploying is just:

```bash
git add . && git commit -m "post: xxx" && git push
```

Everything else is automatic: Cloudflare pulls the code → builds → publishes to the global CDN, usually live within 1-2 minutes.

# Step 9: Get Indexed by Search Engines

Don't forget these after going live (otherwise nobody can find you):

1. Confirm `https://your-domain/robots.txt` allows crawlers (`User-agent: *` + `Allow: /`)
2. Confirm the sitemap is reachable: `/sitemap.xml`
3. Go to [Google Search Console](https://search.google.com/search-console), add your site with the **Domain** property type, and verify via DNS TXT record (if the domain is on Cloudflare, just copy the TXT value and add a record there)
4. After verification, submit the sitemap: `sitemap.xml`
5. Use the **URL Inspection** tool on your homepage and request indexing

Google takes days to weeks for first-time indexing; afterwards, new posts are discovered automatically through the sitemap.
